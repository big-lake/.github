Design Principles
01

Loose Coupling

Each repo owns one concern. Repos communicate through APIs, GCS paths, and the vector DB — never internal implementations.

02

Infra Owns Deployment

All GCP infrastructure is Terraform in one repo. Application repos define logic and config, never resources.

03

Knowledge → Intelligence

Knowledge ingests and embeds. Intelligence retrieves and reasons. Separate repos, separate concerns, by design.

04

BFF Pattern

The UI talks to one API. That API orchestrates OpenMetadata, DuckDB/GCS, and the intelligence service, shielding the frontend from backend topology.

05

Config-Driven Pipelines

New datasets are YAML files, not code changes. ETL pipelines are parameterised by configuration, not hardcoded logic.

06

AI Structure, SQL Logic

AI (Gemini) finds headers and data boundaries. All transformation logic is deterministic DuckDB SQL — testable and auditable.
