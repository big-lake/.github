Design Principles

1

Loose Coupling

Each repo has a single responsibility. No repo directly depends on another's internals. Communication is through well-defined interfaces: APIs, GCS paths, vector DB.

2

Infra Owns Deployment

All serving infrastructure (VMs, databases, vector DBs) is provisioned from infra. Application repos define config and logic, not infrastructure.

3

Knowledge Produces, Intelligence Consumes

Knowledge ingestion and RAG logic are separate concerns in separate repos. knowledge writes embeddings, intelligence retrieves and reasons over them.

4

BFF Pattern

The UI talks to one API (api). The API orchestrates all backend services — OpenMetadata, GCS queries, intelligence. One surface, many backends.

5

Config-Driven Pipelines

ETL pipelines are defined by YAML configuration. Adding a new dataset means adding a YAML file, not writing new code.

6

AI for Structure, SQL for Logic

In ETL, AI handles structural parsing (finding headers, data boundaries). All transformation logic is deterministic DuckDB SQL — testable and reproducible.
